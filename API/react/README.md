### Вкладка «Пользователи (API)»

- Загружает список пользователей при монтировании
- По клику загружает детали выбранного пользователя
- Показывает `loading / error / empty / data` для каждого запроса
- Отменяет устаревшие запросы через `AbortController` — защита от race condition
- Подсвечивает выбранного пользователя

### Вкладка «Регистрация (форма)»

- Поля: имя, email, пароль, повтор пароля, возраст, согласие
- Валидация: длина, формат email, буквы+цифры в пароле, совпадение паролей, возраст 18–120
- Показ/скрытие пароля
- Ошибки показываются только для «тронутых» полей (`touched`), а при сабмите — для всех
- Кнопка «Зарегистрироваться» disabled, пока форма невалидна
- Автофокус на первое невалидное поле при сабмите (через `useRef` и `document.querySelector`)
- Сброс формы и возврат фокуса на первое поле после успеха

## Чему учит проект

### Часть 5 — `useEffect` и API

- Что такое **побочный эффект** и почему его нельзя делать в теле рендера
- Три режима массива зависимостей:
  - `[]` — один раз после монтирования
  - без массива — после каждого рендера
  - `[dep]` — при изменении зависимости
- **Cleanup-функция**: когда вызывается и зачем нужна
- Почему `useEffect(async () => ...)` — ошибка и как правильно (`async`-функция внутри + вызов)
- Проверка `res.ok` после `fetch` (fetch **не** бросает ошибку на 404/500)
- Три состояния для любого запроса: `loading`, `error`, `data`
- Отмена запросов через `AbortController` при смене параметра и размонтировании
- Вынос работы с API в отдельный модуль (`src/api/users.js`)
- Ранние `return` для состояний загрузки/ошибки/пустоты

### Часть 6 — формы и `useRef`

- **Controlled** vs **uncontrolled** компоненты: когда что использовать
- Один `handleChange` на всю форму через `[name]` и тернарник для checkbox
- **Ошибки — производные**, а не в `state` (`validateForm(form)` на каждом рендере)
- Паттерн **`touched`** — ошибки только после `blur` или сабмита (правильный UX)
- `useRef` для доступа к DOM-элементу: автофокус, фокус на ошибку
- `useRef.current` **не** вызывает ререндер (в отличие от `useState`)
- Показ пароля через `type={showPassword ? 'text' : 'password'}`
- `noValidate` на форме + своя валидация
- Валидация вынесена в чистую функцию (`utils/validation.js`) — легко тестировать
